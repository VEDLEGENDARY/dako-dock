# Dako v3 plan

Audience: Codex working in this repo. Read this whole file before editing. Dako 2.0.0 is the baseline.

Priority design brief: [DOCK_REQUIREMENTS.md](DOCK_REQUIREMENTS.md), preserved verbatim from the user's attachment.
Apply V3 features to that floating dock and its island. Track implementation and open acceptance separately in
[DOCK_COMPLIANCE.md](DOCK_COMPLIANCE.md); this roadmap is not a declaration that every acceptance check is complete.

## Goal

Dako is a floating dock that can replace the Windows taskbar for daily use with explicit desktop consent. It must do what the taskbar does (pinned apps, running apps, previews, clock, tray-class status, quick settings, launcher/search) and add things the taskbar lacks (wallpapers, calendar, weather, richer stats). The look stays paper, ink and orange, with the existing motion system.

## Hard constraints

- C++20, Win32, Direct2D, DirectWrite, DirectComposition. No Electron, WebView, JavaScript runtime or background web server.
- WinHTTP is allowed for weather. It must be opt-in, send only coordinates or a city name, and cache results.
- Keep MSVC `/W4 /WX`. Keep the 127-fixture render verification, motion tests, async tests and lifecycle harness passing. Extend them for new views.
- Idle behavior: no new perpetual timers. Prefer events (WinEvent hooks, shell hook, `WM_SETTINGCHANGE`, device notifications). Sampling timers run only while the relevant view is visible.
- No AI, voice, microphone or dictation features.
- Normal launch must not alter Explorer. Taskbar suppression stays opt-in with the existing recovery guard process.
- Code style: concise, lines at most about 120 characters in new code, short comments. Do not add end-of-function comments.

## Findings from the 2.0.0 code (why v3 exists)

1. `LayoutEngine.h` hard-codes a different body height per view (Today 350, Stats 270, Controls 348, Wallpaper 256, Clipboard 270, Power 88, Apps 320 to 480). The island resizes on every tab change. The editorial header is 144 DIP tall when height is at least 520, which is about 40% of the body.
2. The Night light and Dark mode tiles only call `ShellExecute("ms-settings:...")` (main.cpp, `case Night` and `case Dark`). Audio also only opens Settings. There is no brightness control and no output device list.
3. `ProximityTimer` runs every 100 ms forever (main.cpp, `SetCoalescableTimer(window,ProximityTimer,100,nullptr,50)`). The catalog thread wakes every 5 s and calls `CoCreateInstance(IDesktopWallpaper)` to poll the wallpaper (`DesktopCatalog::PollTheme`). docs/PROJECT.md claims the app blocks idle. Make the docs and code agree.
4. `WallpaperReveal` captures the whole virtual screen with `BitBlt` (up to 32M pixels) and rebuilds a window region every 16 ms for a 680 ms effect.
5. Single island, single monitor (`placementMonitor`, reset on `WM_DISPLAYCHANGE`). Work areas are forced to full monitors in `Shell::PositionRail`.
6. Dead code from the rail experiment: `rail_`, `RailProcedure`, `RailCallback`, `railRegistered_` in `DesktopShell.h`.
7. `main.cpp` is about 2,000 lines and 200 KB with some lines over 800 characters. The `Island` class owns every view.
8. Clipboard is one current-text preview with no history. Today holds a clock, 7-day strip, battery, focus timer and five tasks in 800 by 350. Stats ranks processes by working set only and has no history. Power takes a whole tab.
9. Hiding `Shell_TrayWnd` also hides the notification area, so with suppression on the user loses tray icons.
10. Fullscreen detection is a heuristic (no `WS_CAPTION` and covers the monitor) in `UpdateContext`.
11. Three separate INI stores: `appearance.ini`, `tasks.ini`, `apps.ini`.

## Decision: floating dock, with desktop consent

The priority reconciliation request supersedes the full-width bar design. `layoutMode` is `dock` (default preference)
or `notch`; saved `bar` values migrate. First normal run asks once “Use Dako as my taskbar”. Without consent, normal
launch shows the notch and neither changes Explorer nor registers an AppBar. Preview can show a non-reserving dock.

### Dock spec

- One centered content-fit capsule, about 56 DIP tall and 8 DIP above the edge, with rounded ends, paper/ink outline
  and soft lower rim. Width is bounded to 90% of the monitor; app overflow scrolls. No second strip is painted.
- Desktop opt-in starts the existing guard before Explorer suppression, then reserves an invisible 72-DIP AppBar
  strip per monitor using ABM_NEW, QUERYPOS, SETPOS and REMOVE. The strip scales with DPI/text size. DirectComposition
  clears outside the capsule; HTTRANSPARENT plus a native capsule region lets other-process windows receive input.
- Launcher zone: Dako mark opens Apps; search opens the same Ctrl+Alt+K command palette. App zone: merged pinned/running
  AUMIDs, running dots, unpinned divider, reorder/new instance, tooltips and DWM previews. No per-window dock buttons.
- Status zone: user-chosen weather/Wi-Fi/volume/battery/clock, clock as the only text, plus a status overflow popover.
  Show desktop and Task view live in the palette; optional dock icons default off.
- Finite spring magnification and neighbor spacing; reduced motion disables it. High contrast has a solid surface,
  strong outline and no shadow. The existing island opens upward, anchored to the clicked zone.
- QUNS and ABN_FULLSCREENAPP hide the dock. Preserve monitor filtering, Explorer registration recovery and guard
  restoration. Do not force SPI_SETWORKAREA in dock mode. Auto-hide remains optional and unimplemented.

## UI system rules

- One fixed island body height for all tabs (about 360 DIP). Content scrolls inside cards. The island never resizes on tab change; only the Apps view may grow to a defined maximum.
- Header 56 to 64 DIP: wordmark, underlined tabs, time and battery chips. Show the large serif editorial title only when the panel is tall.
- Three card sizes only: tile, wide tile, full-width card. Use the existing constants (padding 20, gap 12, card radius 14, panel radius 20).
- One motion curve and two durations. Respect reduced motion and high contrast exactly as 2.0 does.
- All new views need hit-test bounds, accessibility names (`IslandAccessible`), keyboard traversal, and fixture renders at the existing 5 DPI by 4 text-size matrix.

## Tabs (five plus footer)

Tabs: Controls, Today, Apps, Stats, Wallpaper. Clipboard and Power leave the tab bar.

### Today (home)

- Left: large clock, long date, weather (temperature, condition, high and low).
- Center: month grid with event dots and the next three events.
- Right: task list (raise the five-task cap to about 20, scrolling), compact focus timer row.
- Battery moves to a header chip. World clocks and a stopwatch are one tap away.
- Weather: Open-Meteo (no API key), WinHTTP, manual city search first, then optional Windows location. Cache about 30 minutes. Refresh on view open or timer only while Today is visible. Opt-in setting; document that only coordinates or city name are sent.
- Calendar: month grid, local events, and ICS URL subscription (works with Google and Outlook private feeds). Parse non-recurring events plus `FREQ=DAILY|WEEKLY|MONTHLY` first. Store the URL in settings; never log it.

### Controls

- Dark mode becomes a real toggle: write `AppsUseLightTheme` and `SystemUsesLightTheme` under `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize`, then broadcast `WM_SETTINGCHANGE` with `ImmersiveColorSet`.
- Night light stays a clearly labeled shortcut (no public API known). Label it as a Settings link, not a toggle.
- Brightness slider: DDC/CI for external monitors, WMI for laptop panels. Hide the control when unsupported.
- Output device list via `IMMDeviceEnumerator::EnumAudioEndpoints`. Switching the default endpoint has no public API. Decide explicitly: either use the undocumented `IPolicyConfig` behind a clearly isolated file, or keep an "Open sound settings" link. Default to the link until the user approves the risk.
- Add airplane mode (WinRT radios, reuse existing wireless code), Win+P (`DisplaySwitch.exe`), screen snip (`ms-screenclip:`).

### Apps (island launcher)

- Pinned row (reuse starred apps from `apps.ini`), Running section (from the window list), search, recents.
- Remove the magnifying rail unless the dock's app zone reuses it.

### Stats

- 60-second sparklines for CPU, RAM, network (ring buffers in memory only).
- Top processes by CPU (per-PID time deltas between samples) with a toggle for memory.
- All fixed volumes, battery time remaining, uptime.
- Keep sampling only while the tab is visible. Keep `HardwareStats` worker design.

### Wallpaper

- One grid with a source filter (Collection, My folder, Current). Replace the separate modes.
- Per-monitor apply and fit mode via `IDesktopWallpaper` (`GetMonitorDevicePathAt`, `SetWallpaper(monitorId, path)`, `SetPosition`). Slideshow via `SetSlideshow` as a later step.
- Optional day and night pair.
- `WallpaperReveal` defaults off. If kept, cap capture size and document the cost. Offer a plain crossfade instead.
- Replace the 5 s wallpaper poll with a `WM_SETTINGCHANGE` handler for wallpaper changes.

### Footer menu

- Power (Lock immediate; Sleep, Restart, Shut down with default-cancel confirmation as in 2.0) lives in an island footer menu.
- Clipboard: either remove or make it a Ctrl+Alt+V palette with memory-only history of about 25 items, never persisted. If kept, honor the clipboard formats `ExcludeClipboardContentFromMonitorProcessing` and `CanIncludeInClipboardHistory`, and clear on exit.

## Taskbar parity

| Feature | Approach | Notes |
|---|---|---|
| Running apps | Extend the existing `SetWinEventHook` range (foreground, name change, cloak and uncloak) and keep the `seen_` map as the window list | new `WindowList.h` |
| Eligible windows | Visible, not cloaked, no owner or `WS_EX_APPWINDOW`, not `WS_EX_TOOLWINDOW`, handle UWP frame windows | filter unit-tested |
| Previews | `DwmRegisterThumbnail` | test with elevated windows |
| Flash | `RegisterShellHookWindow`, `HSHELL_FLASH` | pulse the icon |
| Badges, progress | No public third-party observer/getter | capability decision recorded in 3.3 |
| Pinned apps | Reorderable, saved in settings | middle-click opens a new instance |
| Win+number, drag reorder | Standard shortcuts | verify Win+number behavior with Explorer's bar hidden |
| Show desktop, task view | Palette actions; optional dock icons | off by default |
| Multi-monitor | One dock per monitor, windows filtered per monitor | replaces `placementMonitor` |
| Tray | Native status overflow popover | chosen; no private Explorer tray-icon mirror |
| Notifications | Spike first: check whether the Windows notification listener works for an unpackaged exe or needs MSIX | do not commit before the spike |

Known limit: a non-elevated Dako cannot activate or close elevated windows (UIPI). Document it and test it.

## Architecture work (do first, in 3.0)

1. Split `main.cpp`: `Island.cpp`, one header per view (`TodayView.h`, `ControlsView.h`, `AppsView.h`, `StatsView.h`, `WallpaperView.h`), services (`WeatherService.h`, `CalendarService.h`, `WindowList.h`, `DockShell.h`). Behavior must be identical after the split; run all verification before and after.
2. Merge `appearance.ini`, `tasks.ini`, `apps.ini` into one versioned settings store with migration from the three old files.
3. Delete the dead rail code in `DesktopShell.h`.
4. Replace the wallpaper poll with a settings-change event. Decide whether the 100 ms proximity timer becomes a small hot-zone window that only receives mouse events (notch mode only; dock mode needs no proximity polling).
5. Update README and docs/PROJECT.md so idle-behavior claims match the code.

## Roadmap and acceptance

### 3.0 Foundation and Today
- Architecture work above. Fixed body height and slim header. Five tabs plus footer menu.
- Today rebuilt with weather, calendar and tasks.
- Accept: all existing verification still passes; fixtures cover the new views at all DPI and text tiers; idle CPU sample (60 s) no worse than 2.0.

### 3.1 Dock and running apps
- Dock mode with AppBar registration and clean removal on exit and crash. Pinned and running apps, previews, flash, fullscreen hide via QUNS and `ABN_FULLSCREENAPP`, per-monitor docks.
- Accept: maximized browser content is not covered; work area restored after exit and after a forced kill (extend `scripts/test-shell.ps1`); Explorer restart recovery works.

### 3.2 Real controls, stats and wallpaper
- Dark toggle, brightness, device list, airplane mode. Stats history and CPU-ranked processes. Wallpaper grid, per-monitor apply, fit mode.
- Accept: unsupported hardware hides controls instead of failing; no change to Windows settings in automated tests (use inert fixtures as today).

### 3.3 Parity extras
- Public recent/frequent application documents through IApplicationDocumentLists and a native status popover are implemented.
- Capability decision: custom third-party Jump List tasks and badge/progress observation lack a public getter. ITaskbarList3
  setters cannot read another app's state. Do not ship fabricated indicators or private Explorer hooks.
- Notification-listener spike is read-only and requests no permission. On this unpackaged host, access reports Allowed, but NotificationChanged registration fails with `0x80070490`.
  No contents were queried. Event-driven integration is deferred until a working packaging/consent design exists.

## Out of scope for v3

Full shell replacement, startup installation, widgets or news feed, toolbars, pen workspace, voice or AI features, cloud account calendar sync (OAuth), temperature sensors that need drivers.

## Testing rules

- Add fixture data for weather and calendar that never touches the network or real accounts.
- Unit-test the window eligibility filter, ICS parsing (including recurrence), AppBar rectangle math and DPI conversion in `tests/`.
- Manual acceptance on hardware (record results in docs/VERIFICATION.md): AppBar reservation with a maximized browser, multi-monitor changes, elevated window behavior, brightness on laptop and external display, fullscreen game hide.
- Do not claim results that were not measured on a real run.

## Current implementation status

3.0 foundation/Today, 3.1 dock plumbing and 3.2 controls/stats/wallpaper are implemented and retained in separate runnable
build folders. The 3.3 reconciliation changes the current surface to the dock above while retaining their features.
The 3.3 supported parity features and API-limited decisions are listed above; unsupported features are not claimed complete.
Dako-owned theme, volume/mute, brightness, radios and wallpaper are journaled before writes and restored on exit/crash.
Credentials, pairing and network connection changes are delegated to Windows Settings; no rollback of passwords is attempted.
Day/night wallpaper pairs, slideshows, OS location, full recurrence parsing and auto-hide remain optional/deferred.
Physical hardware acceptance and the unavailable Explorer screenshot are recorded in docs/VERIFICATION.md. V3_1.md remains
an independent suite roadmap; its first partial S0 implementation is tracked in docs/MODULES.md.
