## Relationship to V3.md

V3.md defines the dock, the island and the baseline views. This file builds on it and does not replace it. The earlier V3_1 plan (Google Calendar, Pexels wallpaper search) is shelved. Nothing here depends on it.

- This file owns the command palette (hotkey Ctrl+Alt+K), the per-app mixer and the action registry. Implement each once and share it with the CLI and URL scheme.
- Calendar and wallpaper sources stay as specified in V3.md (local events, ICS subscription, local wallpaper folders). External services such as Google Calendar OAuth or Pexels can be added later as optional modules through the module framework below.
- Phase names here (S0 to S8) are separate from V3.md (3.0 to 3.3). Build order: V3.md 3.0 and 3.1 first, then S0, then the rest in order.

## Vision

Dako stops being a small accessibility dock. It becomes the one native Windows app that replaces the taskbar and the pile of utilities people install around it (volume mixers, clipboard managers, window snappers, brightness tools, system monitors, launchers, capture tools, uninstallers).

Reference for scope only: Vorssaint (https://github.com/vorssaint/vorssaint-utils), a free macOS menu bar toolkit that bundles per-app volume, a system monitor, an app switcher, window layouts, Dock previews, clipboard history, snippets, a file shelf, a command bar, capture tools, an uninstaller and more. Its most useful ideas are the modular Features hub, presets, per-feature permission explanations and the local-first privacy stance.

Legal rule: Vorssaint is GPL-3.0 and its name, icon and look are trademarked. Do not copy its source, text, icons, screenshots or layout. Build every Dako module from Microsoft documentation and Dako's own design. Use Vorssaint only as a list of problems worth solving.

## What "much better" means (measurable, not a slogan)

A literal 10x is not a testable claim. Dako beats a menu bar toolkit in these concrete ways, and each is a requirement:

1. **Replaces the taskbar, not a tray icon.** Dock, island, palette and HUDs are one surface (V3.md). Modules appear inside it and never add a second bar or strip.
2. **One command palette over everything.** Apps, windows, files, clipboard, snippets, settings pages, system actions, calculator, units, and every module's actions.
3. **Scenes with triggers.** A scene (Work, Gaming, Presentation, Night) changes wallpaper, volume, brightness, hidden or shown dock and keep-awake. Triggers: app focus, monitor connected, power state, time, Wi-Fi network.
4. **Modules that truly unload.** A disabled module installs no hook, runs no timer, holds no memory beyond a stub. A test proves it.
5. **Published performance budget, enforced.** Each module declares a RAM and CPU budget. `scripts/measure.ps1` checks them. The app shows its own cost per module.
6. **Verifiable privacy.** An in-app ledger lists every active hook, every outbound request (host and reason), and every file or registry location written. A global Offline switch blocks all network use.
7. **Automation.** `Dako.exe --run <action>` command line and a `dako://` URL scheme, so Task Scheduler, Stream Deck, AutoHotkey or scripts can drive any module.
8. **Native and light.** C++20/Win32 only, no web engine. The 2.0 budget stays the bar: about 0.07% idle CPU measured over 60 s.
9. **Accessible by default.** Every new view meets the 2.0 standard (names, keyboard traversal, high contrast, reduced motion, text scaling).
10. **Signed, updatable, reversible.** Signed releases, `winget` install, update with signature check and rollback, crash recovery for anything that changes system state.

## Hard constraints (carry over from V3.md)

- No Electron, WebView, JavaScript runtime or background web server. WinHTTP is allowed only for visible, opt-in features.
- No AI, voice, microphone or dictation features. Anything touching a microphone is listed under Open decisions, not built.
- `/W4 /WX`; existing fixture, motion, async and lifecycle tests keep passing. New modules add fixtures at the existing 5 DPI by 4 text-size matrix.
- Anything that changes system state (brightness, audio routing, power settings, input remapping) records the previous value and restores it on exit, crash, and when the module is disabled. Reuse the recovery guard pattern from `DesktopShell.h`.
- Low-level keyboard or mouse hooks (`WH_KEYBOARD_LL`, `WH_MOUSE_LL`) run on a dedicated thread with its own message loop, do minimal work in the callback, and never block. Windows removes slow hooks silently, so measure callback time and fail safe. Hooks install only while a module that needs them is enabled.
- No telemetry, no account requirement for core features, no cloud. Settings export is a local file. (Account-based providers are deferred and would be optional per provider.)

## Module framework (build first, phase S0)

Each feature is a module behind one interface, in its own header and source file.

```
struct Module {
  id, name, summary, category
  needs: list of declared capabilities (see ledger)
  budget: ram_mib, idle_cpu_percent
  Start(), Stop()               // Stop must release everything
  Actions: id, label, handler   // exposed to palette, CLI and URL scheme
  Settings: schema + defaults
  Surfaces: any of palette action, island view, dock status glyph, transient HUD capsule (never a new bar)
}
```

- **Registry and Features hub.** A settings page lists all modules with Install/Remove (enable/disable). Disabled modules vanish from palette, dock, island and shortcuts. Re-enabling restores their settings.
- **Presets.** Minimal, Taskbar, Power user, Creator. A preset is a list of enabled modules plus defaults. First run shows presets, then only asks for what the chosen modules need.
- **Capability ledger.** Windows has no permission popups for most of this, so Dako declares and shows them: `keyboard-hook`, `mouse-hook`, `clipboard-listener`, `screen-capture`, `network:<host>`, `registry-write:<key>`, `file-write:<path>`, `needs-admin`, `power-state`, `device-control`. The page shows which module uses each, a live indicator when a hook is active, and a warning when a capability is declared but no enabled module uses it.
- **Dock surface rules.** The status zone holds at most five glyphs, chosen by the user. Modules default to palette actions and island views. A module may show a transient capsule that rises from the dock (HUDs, live activities) and must disappear on its own. Review every new surface against the V3.md design principle.
- **Own-cost dashboard.** Per-module RAM, CPU and hook callback time, sampled only while that page is visible.
- **Settings.** One versioned store from V3.md, plus export and import as a single file. Per-monitor and per-app overrides are first-class.
- **Self-test.** A hidden `--module-check` mode starts and stops every module 50 times and asserts no leaked handles, hooks, timers or windows. Add it to `scripts/test-live.ps1`.

## Module catalog

Order is the build order. Windows APIs are starting points to verify, not guarantees. Anything marked RISK needs a spike and a written decision before building.

### S1 Command palette extensions, clipboard, snippets, shelf

- Command palette, built here. Hotkey Ctrl+Alt+K, one action registry shared with the CLI and URL scheme. Sources: apps, open windows, files (Windows Search index through its documented query interfaces), clipboard history, snippets, every `ms-settings:` page, module actions, calculator and units, and system commands (lock, sleep, restart, empty Recycle Bin, toggle dark mode, hide desktop icons, eject drives, show desktop, task view). Saved scripts always ask for confirmation. It replaces Start search and is opened from the dock's search icon.
- Learned ranking stored locally. Acceptance: opens in under 100 ms from the hotkey after first use; works with a screen reader; no network.
- **Clipboard history** via `AddClipboardFormatListener`: text, images, file lists. Memory-only by default. Optional persisted history encrypted with DPAPI. Pin, search, preview, paste as plain text. Respect the `ExcludeClipboardContentFromMonitorProcessing` and `CanIncludeInClipboardHistory` formats. Auto-clear after a delay, on lock or on sleep.
- **Clean URL:** strip tracking parameters from copied links, manual or automatic.
- **Snippets:** ship the searchable insert menu first. Trigger expansion needs a keyboard hook and `SendInput` (RISK: antivirus heuristics and secure fields; never expand in password fields).
- **Shelf:** small drop window using OLE `IDropTarget`; park files, text and links while dragging, drop or share later.
- **Keep awake:** `SetThreadExecutionState` with timers and rules (while selected apps run, on AC power, with an external display). Lid-closed behavior changes power settings, so record and restore the original setting (RISK).

### S2 Windows and displays

- **Window layouts.** Snap zones, saved layouts, restore earlier positions, move between monitors, edge and modifier-drag triggers. Use DWM extended frame bounds to compensate for invisible borders (already done in `ReflowMaximized`).
- **App switcher.** Live previews with `DwmRegisterThumbnail`, search, per-display filter, simple mode without thumbnails. Replacing Alt+Tab needs a low-level keyboard hook (RISK). Default to a separate hotkey and make Alt+Tab takeover an opt-in setting.
- **Virtual desktops.** Only documented `IVirtualDesktopManager` features by default. Switching or moving desktops uses undocumented interfaces; do not ship without a decision (RISK).
- **Displays.** Brightness per monitor: DDC/CI through the Dxva2 monitor functions for external displays, WMI for laptop panels. Software dimming fallback. Hide controls when unsupported. Restore on exit.
- **Window rules.** Per app: open on a given monitor, start maximized, always on top, pin to all desktops where supported.

### S3 System

- **Monitor.** CPU, per-core, GPU engines (PDH, already used), memory, disk, network, battery health (design versus full-charge capacity through the battery IOCTLs), uptime, top processes by CPU and by memory, 60 s and 24 h history rings. Sample only while visible or while an alert rule needs it.
- **Temperatures and fans.** Not without a kernel driver. Out of scope unless the user approves an optional external sensor provider. Do not ship an unsigned driver.
- **Network.** Live up and down per adapter, session totals, local IP, public IP only on explicit action, speed test (opt-in, visible). Per-process traffic needs ETW and admin; optional.
- **Alerts.** Sustained CPU, memory pressure, low disk, low battery, high network. Show in the dock status zone or island, and as a transient capsule instead of a tray balloon. Rules have thresholds, durations and quiet hours.
- **Port manager.** `GetExtendedTcpTable` and `GetExtendedUdpTable` with owning process; end a process with confirmation. Elevated processes need Dako run elevated; say so in the UI.
- **Readouts.** Choose which numbers show beside the clock in the dock's status zone.

### S4 Audio

- **Per-app mixer.** Built here. Per-app volume and mute for audible sessions, pin and reorder favorites, hide inactive sessions. Core Audio sessions (`IAudioSessionManager2`, `ISimpleAudioVolume`). Opens from the dock's volume glyph.
- **Boost above 100%.** Session volume tops out at 100%. Boosting needs an audio processing object or loopback re-render. RISK: spike and decision first.
- **Per-app output device.** Windows has this in Settings through undocumented interfaces. RISK; default to "Open sound settings".
- **Output switcher.** Listing endpoints is documented. Changing the default endpoint is not (undocumented `IPolicyConfig`); needs approval.
- **Safety.** Lower volume when headphones disconnect (device notifications already exist in `AudioDeviceSink`).
- **HUDs.** Dako draws its own volume, brightness and Caps Lock HUDs as a small capsule that rises from the dock. Hiding the Windows flyout is hacky and fragile; make it opt-in and test across Windows 11 builds.

### S5 Capture and create

- **Capture engine.** `Windows.Graphics.Capture` for windows and monitors. Desktop Duplication as fallback.
- **Screenshot.** Area, window, screen, scrolling page; annotate, crop, redact, backgrounds, pin to screen.
- **Recording.** Media Foundation H.264 encode with a separate system-audio track; trim, GIF export through WIC. Microphone track is an Open decision.
- **Text from screen.** `Windows.Media.Ocr`, offline. QR reading needs a small decoding library; ask before adding a dependency.
- **Color picker.** Magnifier, copy as HEX, RGB, HSL, C++ and CSS.
- **Sharing.** Expiring links need a server and are out of scope. Save, copy and open with another app only.
- **Conflict note.** Windows already uses Win+Shift+S. Pick a different default hotkey and do not hijack Print Screen unless the user opts in.

### S6 App management

- **App updates.** Read installed apps and run `winget` for managed updates; parse its output defensively or use its COM API. Show a list, update one or all, or open the app's own updater.
- **Uninstaller.** Enumerate registry uninstall keys and packaged apps; run the app's own uninstaller; then scan documented leftover locations (AppData, ProgramData, install folders, startup entries) and show everything before deleting. Move files to the Recycle Bin with `IFileOperation`. Never delete without a visible preview.
- **Cleaner.** Temp files, caches, thumbnails, logs; manual or scheduled; always previewed; never touch user documents. Windows has Storage Sense, so differentiate through app-level leftovers and clear previews.
- **Startup manager.** List and toggle startup items with clear names.
- **Package manager UI.** Search, install and remove through `winget`.

### S7 Input tools (high risk, ship last)

All of these need low-level hooks and will draw antivirus attention. Each is an independent module, off by default, with the hook indicator in the ledger.

- Smooth scrolling, scroll direction per device, horizontal scroll while holding a key, pointer acceleration toggle (`SPI_SETMOUSE`, restored on exit), side-button actions, button-to-shortcut mapping, extra-click filter, key debounce, Caps Lock or a right-side modifier as a super key with a tap action, focus-follows-mouse, per-app exclusions.
- Close protection for Alt+F4 (hold or double press) per app.
- Acceptance: no input is ever lost or delayed on hook timeout; disabling restores normal input instantly; a panic hotkey disables every input module.

### S8 Live activities, scenes, automation

- **Live activities as a capsule rising from the dock, expandable into the island:** now playing with controls, timers and focus sessions, next calendar event countdown (V3.md calendar), charging and battery, downloads (only where a reliable source exists), volume and brightness HUDs, notifications once the spike from V3.md passes.
- **Scenes.** Named bundles of module settings with triggers (app focus, monitor connect, power state, time, SSID). Preview and undo. Manual activation from palette and hotkey.
- **Radial menu and quick panel.** Customizable wheel and floating palette of favorite actions, with profiles and submenus.
- **Scratchpad.** Autosaved tabbed notes, Markdown preview and export.
- **Cleaning mode.** Block keyboard and mouse input with a visible indicator. Use `BlockInput` where allowed; always keep a documented way out.
- **CLI and URL scheme.** `Dako.exe --run module.action [args]`, `dako://module/action?x=y`. Same action registry as the palette. State-changing URL actions require a confirmation prompt so web pages cannot trigger them silently.

## Product polish (required, not optional)

- **Signing and install.** Code-sign releases (certificate or Microsoft's signing service). Publish to `winget`. Provide a portable ZIP. Unsigned builds trigger SmartScreen; say so clearly until signing exists.
- **Updates.** Check on a visible schedule, verify signature and checksum, keep the previous version for rollback.
- **Docs in `docs/`:** PRIVACY.md (what leaves the PC), PERMISSIONS.md (every capability in plain words), TROUBLESHOOTING.md, SECURITY.md with a reporting address.
- **Localization.** All user strings in resource tables from the start; no hard-coded English in new code.
- **First run.** Preset picker, then one screen per enabled capability explaining what it does and how to undo it.
- **Brand.** Keep paper, ink, orange. Do not imitate Vorssaint's look.

|---|---|---|
| S0 | Module framework, Features hub, presets, capability ledger, own-cost page, `--module-check` | Enable and disable of a dummy module leaks nothing in 50 cycles; the ledger lists a test hook |

| S7 | Input tools | Panic hotkey works; callback time budget enforced in tests |
| S8 | Live activities, scenes, radial menu, scratchpad, CLI and URL scheme | A scene applies and undoes cleanly; URL actions require confirmation |

Record real-hardware results in `docs/VERIFICATION.md`. Do not claim results that were not measured.

## Risks to track

- Antivirus and SmartScreen reactions to hooks, clipboard access, input injection and screen capture. Signing helps; module opt-in and clear docs help more.
- Undocumented APIs (audio routing, virtual desktop switching, Night light) break across Windows updates. Isolate each in one file behind an interface and a feature flag.
- Elevated windows cannot be controlled from a non-elevated Dako. Offer an optional elevated helper only after a security review.
- Scope. Nine phases is a lot for one maintainer. Each phase must ship usable on its own, and any module that misses its budget or acceptance test is cut or deferred, not shipped half-done.

## Open decisions for Ved (Codex must not decide these)

1. License and pricing: free open source, paid, or free core with paid modules. If any Vorssaint (GPL) code were ever reused, Dako would have to be GPL. This plan assumes no reuse.
2. Microphone features (mute-all shortcut, input level) conflict with the current no-microphone rule. Allow or keep excluded?
3. AI agent usage tracking (a Vorssaint feature) conflicts with the no-AI rule. Keep excluded unless changed.
4. Default endpoint switching and per-app audio routing through undocumented interfaces: accept the break risk or link to Settings.
5. Alt+Tab takeover and virtual desktop switching: accept hook and undocumented-API risk, or keep opt-in only.
6. Optional temperature and fan support through an external sensor provider: allow or exclude.
7. Code-signing path and budget.
